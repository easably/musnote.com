# Анимация ожидания и общий стиль для сайта и Flutter

Решение пользователя 2026-11-21. Исполнитель — Cursor, куратор — Claude.

## Зачем

1. Пока API читает ноты, человек видит тонкую бегущую полоску и «Читаем ноты…» (`web/index.html:85`, `.notes-busy` в `chords.css:209–212`). Большой файл разбирается десятки секунд — это скучно и похоже на зависание. Нужна своя анимация, которая «занимает» человека и рассказывает, что происходит: звук → ноты.
2. Стиль живёт в трёх местах, и копии уже разъезжаются:
   - `web/assets/css/design-tokens.css` (48 переменных);
   - `web/assets/css/chords.css`, первые ~25 строк: те же `--mn-*` объявлены заново, плюс цвета ролей `--c-r/t/f/s`;
   - `vocal_note_monitor/lib/theme/musnote_theme.dart`: цвета вписаны руками, плюс разрозненные `Color(0x…)` в виджетах.

## Часть 1. Один источник стиля

**Формат:** `design/tokens/musnote.tokens.json` — один JSON в формате W3C Design Tokens (`$value`, `$type`). В нём:
- цвета: бренд, нейтральные, роли нот `r/t/f/s` с мягкими парами, клавиши — белая, чёрная, подсвеченная;
- шрифты и размеры;
- отступы, радиусы, тени;
- длительности и кривые движения;
- параметры анимации ожидания (часть 2).

**Генератор:** `scripts/build-tokens.js` на Node, без зависимостей. Из JSON пишет:
- `web/assets/css/design-tokens.css` — `:root { --mn-…; --c-…; }`, с шапкой «сгенерировано, не править руками»;
- `vocal_note_monitor/lib/theme/musnote_tokens.g.dart` — `abstract final class MusnoteTokens` с `Color`, `double`, `Duration`, `Curve`.

Флаг `--check`: падает, если сгенерированные файлы не совпадают с JSON (для CI и перед коммитом).

**Переезд:**
- `chords.css` больше не объявляет `--mn-*` и `--c-*`, страницы подключают `design-tokens.css` первым. Проверить все страницы, где сейчас только `chords.css`.
- `musnote_theme.dart` берёт цвета из `MusnoteTokens`; `MusnoteColors` остаётся тонкой обёрткой, чтобы не переписывать виджеты разом.
- Голые `Color(0x…)` в `lib/` заменить токенами там, где цвет совпадает с токеном. Остальные перечислить в «результате».
- `plans/design-system.md`: источник — JSON, CSS и Dart генерируются.

**Проверка:**
- `node scripts/build-tokens.js --check` — ок;
- визуально сайт не изменился (`/`, `/ru/`, `/chords/patterns/`, `/tools/`) — сравнить скриншоты до и после;
- `flutter analyze` чистый;
- `grep -n -- '--mn-green-500:' web/assets/css/*.css` — ровно одно место.

## Часть 2. Анимация ожидания

**Как переносить на Flutter:** не Lottie и не Rive (тяжёлый runtime на вебе, нужен отдельный редактор). Делаем так же, как уже сделаны падающие ноты (`falling-notes.js` ↔ `falling_notes.dart`):
- анимация — формулы от времени `t`: волна, появление нот, цвета из токенов;
- описана в спецификации `design/loading-animation/SPEC.md` с числами из `musnote.tokens.json` (`animation.loading.*`);
- реализована дважды: `web/assets/js/loading-wave.js` (canvas или SVG) и `vocal_note_monitor/lib/widgets/loading_wave.dart` (`CustomPainter` + `AnimationController`);
- чистая геометрия (позиции, фазы, цвет по времени) — отдельные функции без DOM/Flutter. Тест на обеих сторонах сверяет одни и те же контрольные значения (как `falling-notes.test.js`).

**Сначала варианты на выбор пользователю** — без них ничего не встраивать. В `design/loading-animation/index.html` три живых варианта на токенах сайта, у каждого цикл 3–5 секунд, бесконечный:
- **A · Волна → ноты.** Синусоида бежит слева направо. У правого края её гребни отрываются цветными полосками нот и падают на маленькую клавиатуру, клавиши вспыхивают. Это история продукта.
- **B · Ноты на волне.** По спокойной волне катятся круглые ноты цветов ролей (зелёная, оранжевая, синяя), поднимаются на гребнях, исчезают и появляются заново.
- **C · Клавиши-эквалайзер.** Иконка приложения (вариант A из `design/app-icon/`) оживает: белые клавиши разной высоты качаются, как полосы звука, две подсвечены. Связь с иконкой в сторе.

**Общее для всех вариантов:**
- Под анимацией сменяющиеся подписи раз в ~3 с, на языке страницы: «Слушаем запись…» → «Ищем ноты…» → «Раскладываем по клавишам…». Плюс прошедшее время «0:12». Фальшивых процентов нет: API прогресс не отдаёт.
- Через ~20 с подпись «Длинная запись — ещё немного». Через ~90 с — «Это дольше обычного» (дальше возможен обрыв, см. риск ниже).
- `prefers-reduced-motion`: статичный кадр + подписи; на Flutter — `MediaQuery.disableAnimations`.
- Размер: на всю ширину карточки, высота ~140 px. На 375 px не обрезается.
- Ни одного внешнего файла и библиотеки.

**После выбора** (номер допишет куратор):
- веб: заменить `.notes-busy-bar` в состоянии `loading` на 22 страницах, `?v=` поднять;
- Flutter: тот же виджет в `notes_screen.dart` на время запроса к API;
- подписи на 11 языках сайта и в строках приложения.

**Проверка:**
- обе реализации дают одинаковые контрольные точки в тестах (`node …test.js`, `flutter test`);
- на сайте состояние `loading` с задержанным ответом API (перехват `fetch`) показывает анимацию, подписи сменяются, время идёт;
- reduced-motion — статичный кадр;
- Flutter: через `scripts/android-dev-run-hot-reload.sh`, скриншот в `.tmp/device-qa/`.

## Риск, который анимация не решает

Ответ API синхронный. Если настоящий разбор длиннее ~100 с, обрыв может случиться по дороге (Cloudflare, прокси на server8). Анимация это не лечит. Решение «очередь задач + опрос статуса» — архитектурная развилка за пользователем, в этот план не входит.
